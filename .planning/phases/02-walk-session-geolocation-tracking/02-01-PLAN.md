# Plan 02-01: Geolocation Noise Filter, Distance Engine & Dexie Walk Session Store

## Objective
Implement the foreground geolocation tracking and persistence foundation for outdoor walks: pure mathematical utilities for Haversine distance, GPS accuracy cutoff, and stationary displacement filtering; a robust `useGeolocation` React hook with signal status tracking; and a persistent `useActiveWalk` hook integrated with Dexie.js for automatic session recovery across tab reloads and background app transitions.

## User Rules & Context
- **SHELL:** zsh
- **Package Manager:** pnpm
- **Locked Decisions (per CONTEXT.md):**
  - **D-04:** Auto-resumed walk sessions seamlessly restore tracking state with a brief toast notification ("Active walk resumed") and camera fly-to latest GPS fix.
  - **D-05:** Subtle amber status chip in HUD ("Weak GPS ±Xm") when accuracy degrades beyond 35m, quietly pausing breadcrumb recording until accuracy improves.
  - **D-06:** Stationary stops (observing wildlife/photos) do not append duplicate jitter points to the polyline; updates active timestamp while maintaining last known fix.
  - **D-07:** Resuming from background throttling connects the gap continuously to the newly acquired GPS fix and updates cumulative distance via Haversine formula.
  - **D-08:** GPS permission revocation or loss mid-walk keeps session active, showing an actionable top alert with "Re-enable Location" trigger and preserving all prior track points safely.
  - **D-15:** Short/empty walks (< 1 minute or < 25 meters) prompt "Discard Walk" vs "Save Anyway" to prevent cluttering Dexie walk history.

       - Otherwise return { record: true }.
    5. calculateTrailBounds(points: Array<{ lat: number; lng: number }>): [[number, number], [number, number]] | null - returns [[minLng, minLat], [maxLng, maxLat]] bounding box for MapLibre fitBounds.
