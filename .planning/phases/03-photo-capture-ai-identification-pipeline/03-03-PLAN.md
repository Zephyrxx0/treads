# Plan 03-03: `/api/facts` Grounded Fact Extraction, Edibility Scrubber, Interactive Fact Card & `/entry/[id]` Page

## Objective
Implement grounded Wikipedia fact card generation, strict safety scrubbing, and the entry detail interface: build `/api/facts` using Wikipedia lead extracts and Gemma/Gemini structured synthesis with numbered citations, enforce multi-layer regex scrubbing of all edibility/toxicity/medicinal claims, create the interactive `FactCard` component with citation popovers, build the dedicated `/entry/[id]` specimen detail route, and wire specimen thumbnail pins onto the MapLibre trail map, walk HUD, and end-walk summary reel.

## User Rules & Context
- **SHELL:** zsh
- **Package Manager:** pnpm
- **Locked Decisions (per CONTEXT.md):**
  - **D-10:** Interactive cited fact cards: 3 distinct facts with clickable citation pills (`[1]`, `[4]`) toggling an inline popover showing the exact verbatim Wikipedia sentence, accompanied by an "Open in Wikipedia" link pill.
  - **D-11:** Multi-layer defense for edibility scrubbing: strict negative system prompt constraint plus deterministic server-side regex blacklist (`edible|toxic|poisonous|medicinal|remedy|forag*|culinary|tasty`), rejecting/filtering any flagged fact before saving to Dexie.
  - **D-12:** Dedicated `/entry/[id]` detail view: hero photo with pinch/zoom, species common and scientific names, verified taxon badge, interactive fact card, capture timestamp & GPS coordinates pill, and scaffolded "Listen" narration button (for Phase 4).
  - **D-13:** Circular thumbnail marker pins on MapLibre trail: 36px circular badge containing the 160px photo thumbnail with a color-coded taxon ring (green plant, orange insect, blue bird), tapping opens the summary drawer.
  - **D-14:** Walk HUD specimen count pill: compact glassmorphism chip (`🌱 X finds`) in the top HUD; tapping opens a horizontal quick-drawer of finds during the current walk session.
  - **D-16:** Visual species reel in End Walk Summary Drawer: horizontal scrolling reel of captured organism photos with common names and verified badges right below the distance/time metrics, clicking opens `/entry/[id]`.
- **Component Mandate:** Strictly compose readymade shadcn Base UI primitives (`Card`, `Popover`, `Sheet`, `Button`, `Badge`, `ScrollArea`).

  <action>
    Create app/api/facts/route.ts:
    1. Enforce IP rate limiting via `checkRateLimit(req, 'facts')`.
    2. Accept POST payload: `{ wikipediaTitle: string; scientificName?: string; commonName?: string }`.
    3. Fetch Wikipedia lead sentences via `getWikipediaLeadSentences(wikipediaTitle)`.
    4. If no sentences found, return 404 or empty facts payload.
    5. Call `@ai-sdk/google` (Gemma `gemma-2-9b-it` or Gemini Flash fallback) with prompt:
       - Input: Numbered sentences `[1] ... [2] ...`.
       - Instructions: "Synthesize a short summary (max 40 words) and up to 3 distinct interesting biological facts (max 20 words each). Each fact must cite the exact sentence index where the information was found. Do NOT include any claims regarding edibility, foraging, cooking, toxicity, or medicinal usage."
       - Schema: `summary: z.string()`, `facts: z.array(z.object({ sentenceNumber: z.number(), text: z.string() }))`.
    6. Filter generated facts through `validateCitations` and `containsSafetyViolations`.
    7. If any fact is flagged, discard it. If all facts are discarded, retry once.
    8. If retry still yields 0 facts, apply fallback: sentence #1 of verified lead section as the single fact.
    9. Cache result in in-memory LRU cache by Wikipedia title (per FACT-06).
    10. Return `{ summary, facts, sourceUrl, sentences, cached: boolean }`.
  </action>

  </verify>
